TaiOne 專案技術評估與發展建議書 (v2.0)

報告日期: 2025年11月04日 架構師: Gemini (Mentor)

序言：執行摘要 (Executive Summary)

TaiOne 專案是一個基於現代化、高效能技術棧（Next.js, tRPC, Prisma）的高品質社群媒體應用程式原型。其架構清晰，程式碼基礎紮實，並已成功實現了自動化的 CI/CD 爬蟲流程。專案在型別安全、開發者體驗和核心功能實現上表現出色，展現了巨大的發展潛力。

然而，專案目前也面臨著幾個關鍵的成長挑戰，主要集中在 自動化測試的缺失 和 CI/CD 流程的不完整。這些是技術債的早期信號，若不加以解決，將會隨著功能的擴展而顯著增加維護成本和迴歸風險。

本報告旨在全面評估專案的當前狀態，並提供具體的程式碼級建議，提出一系列可執行的改進方案，以確保 TaiOne 在未來的開發道路上，能夠兼具快速迭代與長期穩定性。

1. 專案現狀分析 (Project Status Analysis)

1.1. 技術棧評估

優勢:

採用 T3 Stack，提供端對端型別安全。tRPC 消除 API 樣板程式碼，前後端資料交換效率高。

劣勢:

此技術棧對新進開發者有一定學習曲線。

1.2. 架構健壯性

優勢:

pnpm workspaces 的 Monorepo 架構清晰分離 `web` 與 `scraper`，可擴展性高。Prisma 提供強大 ORM。

劣勢:

核心資料同步流程 (從 `SourcePost` 到 `Post`) 缺乏交易完整性，是目前最脆弱的一環。單點失敗可能導致資料狀態不一致。

問題點: 流程分散在 `sync-to-db.ts` 和 `create-posts.ts`。若後者失敗，`SourcePost` 狀態將與 `Post` 脫鉤。

1.3. 程式碼品質

優勢:

配置 ESLint, Prettier, lint-staged 及嚴格 TypeScript 規則，確保風格統一和基礎品質。

劣勢:

程式碼中缺乏註解來解釋「為什麼」，特別是在複雜業務邏輯或 AI prompt 設計上。

1.4. 測試覆蓋率

優勢:

暫無。

劣勢:

測試覆蓋率為 0%。這是目前專案面臨的最大風險。任何修改都缺乏信心，只能依賴手動測試，長期不可持續。

1.5. CI/CD 狀態

優勢:

已建立定時執行爬蟲的 GitHub Actions workflow。實現 Secrets/Variables 分離管理，具備日誌上傳功能。

劣勢:

目前僅為排程任務 (CD)，非完整 CI 流程。不會在 PR 時觸發，無法自動檢查 Linting, Type Checking 和執行測試。

1.6. 文件完整性

優勢:

`GEMINI.md` 作為動態更新的交接文件，提供了寶貴的演進上下文。

劣勢:

缺乏標準化開發者文件，如 `CONTRIBUTING.md` (貢獻指南) 和 `ARCHITECTURE.md` (架構決策紀錄)，增加新成員融入成本。

2. 核心功能模組分析

2.1. 爬蟲模組 (Scraper)

現狀: Reddit 爬蟲已從 Puppeteer 重構為 `snoowrap` 函式庫的穩定 API 呼叫，展現強大問題解決能力。

待辦: 其他爬蟲（如 PTT, BBC）可能仍用基礎方法，穩定性有待驗證與強化。

2.2. AI 內容生成 (AI Generation)

現狀: 能利用 Gemini Vision 進行多模態內容生成，是專案一大亮點。

待辦: AI prompt 較單一，缺乏內容關聯性判斷，產出風格同質化。

2.3. 資料庫同步 (DB Sync)

現狀: 能將爬取的 `SourcePost` 寫入資料庫。

待辦: 缺乏批次處理機制，大量資料時有效能瓶頸。且與 `create-posts` 流程缺乏交易保護。

2.4. 使用者關聯 (User Association)

現狀: 透過 `ensureChannelUser` 機制，能為來源頻道建立「機器人」使用者，是正確的第一步。

待辦: 此為基礎實現，尚未形成完整的、可擴展的使用者系統。

3. 待改進建議 (Actionable Recommendations)

最高優先級 1. 導入整合測試框架 (Jest)

行動: 立即為 `apps/scraper` 的核心邏輯編寫第一個單元測試。

  1. 安裝依賴: `pnpm --filter trend-scraper add -D jest @types/jest ts-jest`
  2. 建立 `apps/scraper/jest.config.js`。
  3. 建立 `apps/scraper/scripts/__tests__/reddit-trends.test.ts`。

理由: 測試是專案長期健康的基石。它能確保未來的重構和新功能不會破壞現有邏輯，是提升開發速度和信心的最佳投資。

程式碼示例 (第一個測試):

// apps/scraper/scripts/__tests__/reddit-trends.test.ts
import snoowrap from 'snoowrap';
// (此處應將原 reddit-trends.ts 的邏輯重構為可匯出的函式)
import { fetchRedditDataWithSnoowrap } from '../reddit-trends';

// 模擬 snoowrap 函式庫
jest.mock('snoowrap');

describe('Reddit Scraper', () => {
  it('should fetch and transform hot posts correctly', async () => {
    // 準備模擬資料
    const mockPost = { title: 'Test Post', toJSON: () => ({ title: 'Test Post' }) };
    const mockGetHot = jest.fn().mockResolvedValue([mockPost]);
    (snoowrap.prototype.getHot as jest.Mock) = mockGetHot;

    const r = new snoowrap({
      /* ...mock credentials... */
    });
    const source = { subreddit: 'all', limit: 1, filename: '', description: '' };

    // 執行函式
    const result = await fetchRedditDataWithSnoowrap(r, source);

    // 驗證結果
    expect(mockGetHot).toHaveBeenCalledWith('all', { limit: 1 });
    expect(result.data.children[0].data.title).toBe('Test Post');
  });
});

高優先級 2. 建立完整的 CI 流程

行動: 在 `.github/workflows/` 目錄下建立一個新的 `ci.yml` 檔案。

理由: 將品質檢查自動化，確保任何進入主分支的程式碼都符合專案的品質標準，從源頭上杜絕錯誤。

程式碼示例 (ci.yml):

name: Continuous Integration

on:
  pull_request:
    branches: [main]

jobs:
  quality_check:
    name: Code Quality Check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Lint
        run: pnpm lint

      - name: Type Check
        run: pnpm --filter web tsc --noEmit && pnpm --filter trend-scraper tsc --noEmit

      - name: Run Tests
        run: pnpm test

中優先級 3. 整合結構化日誌 (pino)

行動: 為爬蟲專案引入 `pino`，並取代 `console.log`。

  1. 安裝依賴: `pnpm --filter trend-scraper add pino`
  2. 在腳本頂部初始化 logger，並替換 `console.log`。

理由: 結構化日誌 (JSON 格式) 易於機器解析，方便未來接入日誌聚合系統 (如 Logtail, Datadog)，並提供更豐富的上下文 (如時間、嚴重級別)。

程式碼示例 (日誌替換):

// Before:
console.log(`🌐 正在抓取 r/${subreddit} 的熱門文章...`);

// After:
import pino from 'pino';
const logger = pino();

logger.info({ subreddit }, `正在抓取 r/${subreddit} 的熱門文章...`);

4. 未來發展方向與架構建議

v1.0 資料庫穩健性：引入交易

目標: 確保資料寫入的原子性，解決目前 `sync-to-db` 和 `create-posts` 流程分離的脆弱性。

架構建議: 將兩個腳本的邏輯合併，並使用 `prisma.$transaction` 將「建立 `Post`」和「更新 `SourcePost` 狀態」包裝在同一個交易中。

程式碼示例 (交易邏輯):

import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();

async function createPostFromSource(sourcePost) {
  // 1. 呼叫 AI 生成內容
  const aiContent = await generateContentFromAI(sourcePost);

  // 2. 在一個交易中完成資料庫寫入
  try {
    const result = await prisma.$transaction(async (tx) => {
      // 建立新文章
      const newPost = await tx.post.create({
        data: {
          content: aiContent,
          authorId: sourcePost.channelUserId,
          // ... 其他欄位
        },
      });

      // 更新來源文章狀態
      await tx.sourcePost.update({
        where: { id: sourcePost.id },
        data: { status: 'PROCESSED' }, // 假設新增一個 status 欄位
      });

      return newPost;
    });
    logger.info({ postId: result.id, sourcePostId: sourcePost.id }, '成功建立文章並更新來源狀態');
  } catch (error) {
    logger.error({ sourcePostId: sourcePost.id, error }, '文章建立交易失敗');
  }
}

v1.0 內容生成智慧化

目標: 提升 AI 內容的品質與多樣性。

架構建議: 設計一個「Prompt 策略引擎」。根據 `SourcePost` 的特性 (如是否有圖、標題長度、內容摘要等)，動態選擇不同的 Prompt 模板 (如 `image-focused-prompt.txt`, `long-form-prompt.txt`)，並傳遞給 AI。

v2.0 擴展爬蟲來源

目標: 增加內容的多樣性與廣度。

架構建議: 建立一個標準化的爬蟲介面 (Interface)。每個新的爬蟲來源都實作這個介面，定義 `fetch` 和 `transform` 方法。這樣可以讓主流程以統一的方式調用不同的爬蟲，降低複雜度。

程式碼示例 (爬蟲介面):

interface Scraper {
  sourceType: string;
  fetch(): Promise<RawData[]>;
  transform(rawData: RawData): SourcePostInput;
}

class RedditScraper implements Scraper {
  // ... 實作
}

  // ... 實作

5. 總結 (Conclusion)

TaiOne 專案的基礎非常出色，技術選型現代，程式碼品質良好。目前正處於從「原型開發」邁向「可持續發展」的關鍵轉捩點。

我們近期在 CI/CD 和爬蟲穩定性上取得的突破，已經為專案的下一階段奠定了堅實的基礎。接下來的重心應 立即轉向自動化測試的建立，這是確保專案能夠健康、快速成長的最重要一步。

只要我們能持續地、有紀律地償還現有的技術債，並按照本報告提供的藍圖穩步前行，TaiOne 專案的未來無可限量。
